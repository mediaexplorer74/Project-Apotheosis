# What it verifies. On the fixed-viewport line (fitwindow=0) rotation used to be a no-op: the
# engine viewport stayed the portrait 720x1080 frame inside a landscape window, the page kept its
# portrait shape (RenderImage is Stretch=None at Top/Left), and a gesture started to the right of
# that frame was outside the page -- reported from the Lumia as "in landscape scroll and pinch do
# not work" while the log showed `pinch: ... rc=0` (the engine itself was alive). Since .57
# OnContentAreaSizeChanged ADOPTS rotation on the fixed line: it swaps the viewport pair
# (720x1080 portrait <-> 1080x720 landscape) through the same posted body the pinch and the fitted
# line use, deferred through _vpDirty if a load owns the engine.
#
# THE MAINTAINER PART: turn the phone 90 degrees into landscape during the `wait 20000` marked
# ROTATE below. The batch holds a DisplayRequest, so the screen stays up.

#   autocmd-log:  rotate: 1080x720 zoom=0.80      the adopt itself (the Crumb in PostZoomAndRepaint)
#   diag:         contents=1080x720               the engine viewport followed the rotation
#   [DG] / no "Simulation paused on mobile"       the gate stays open: 1080/0.8 = 1350 CSS > 870
#   hash pair across swipe/scroll                 a CHANGE proves the engine scrolled; no change
