# Apotheosis 2026-10-20 -- the device acceptance list, run by the app itself.
#
# This is the ARM twin of Src/tools/run-smoke.ps1's thirteen-site list. The x64 script drives the
# app from outside by rewriting LocalState\autocmd.txt and polling stage.txt between sites; Device
# Portal cannot write LocalState (every spelling returns HTTP 500), so on the phone the sequence
# has to travel inside the package and be paced by its own `wait` commands. Same sites, same order,
# same per-site verbs -- the instrument differs, the list does not.
#
# Every site gets, in this order:
#   goto           the navigation (fire-and-forget; the wait below is what observes it)
#   wait <ms>      paced, not polled: the device has no side channel to poll from
#   diag           the engine's own view -- `diag url=` names the DOCUMENT (requirement 4), and on
#                  dzen.ru it is the only field that follows the SSO redirect
#   hash           the frame hash, so two consecutive equal hashes mean a settled frame
#   swipe          the real touch path (requirement 6); logs `swipe end totalMs=`
#   back / hist / forward / diag
#                  requirement 5 on the device -- `hist` separates "Back was refused" from
#                  "Back moved and the page looked the same"
#
# The waits are sized per site from the x64 run's own measurements. They are a ceiling, not a
# prediction: a slow site is simply still loading when the next goto replaces it, and the diag that
# precedes the swipe is the record of what was on screen at that moment. Do not tighten them to
# make the run shorter -- a too-short wait on lenta.ru measures the previous page.
#
# One process, no restart, ten minutes. If the app dies mid-list, the `device-run.done` marker it
# writes before the first command keeps the next launch from silently replaying the same batch.
# Redeploy with a new version to run it again.
